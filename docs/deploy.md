# Публикация на сервере проектов

Инструкция для того, кто ставит приложение на уже работающий сервер. Тестировщикам она не нужна: им достаточно ссылки и пароля сайта.

Сервер описан в `deploy/SERVER.md`. На нём уже есть Docker, Caddy и общая база. Отклик занимает порт `3000` и базу `watch-reviews`. Это приложение сажается рядом: свой каталог, свой порт `3001`, своя база `support_summary`.

Страницы и API здесь — одна программа в одном контейнере. Отдельный каталог `/var/www` и отдельная сборка интерфейса не нужны. Caddy передаёт на контейнер весь сайт, а не только адреса, которые начинаются с `/api`.

Блок `bash` — одна команда. Блоки `caddy`, `yaml` и `dotenv` в терминал не вставляются: это текст файла в `nano`.

Подставьте свои значения вместо `IP-СЕРВЕРА`, `ДОМЕН`, `ПАРОЛЬ-АДМИНИСТРАТОРА`, `ПАРОЛЬ-ПРОЕКТА`, `ПАРОЛЬ-САЙТА` и `СЕКРЕТ-ШИФРОВАНИЯ`.

## Что уже есть и что не трогать

| Что | Где |
| --- | --- |
| Вход | `ssh -i ~/.ssh/otklik deploy@IP-СЕРВЕРА` |
| Сайты | Caddy, файл `/etc/caddy/Caddyfile` |
| Отклик | порт `127.0.0.1:3000`, каталог `/opt/otklik` |
| Общая Mongo | контейнер `mongo`, каталог `/opt/mongo`, сеть Docker `shared` |
| Это приложение | каталог `/opt/support-summary`, порт `127.0.0.1:3001` |

Наружу открыты только порты 22, 80 и 443. Порт `3001` и порт базы наружу не открываются.

Не устанавливайте второй Docker, второй Caddy и вторую Mongo. Не занимайте порт `3000`. Не используйте базу `watch-reviews` и пользователя `otklik`. Не копируйте `.env` Отклика.

Файлы `docker-compose.yml`, `deploy/docker-compose.vps.yml` и `deploy/Caddyfile` из репозитория на этот сервер не подключайте. Первый поднимает свою базу и открывает порт на компьютере разработчика. Второй запускает ещё один Caddy на портах 80 и 443 и ломает уже работающие сайты.

## Домен

У регистратора одна A-запись домена на IP этого сервера. Проверка с Мака:

```bash
dig +short ДОМЕН
```

В ответе должен быть IP сервера. Пока записи нет, Caddy не выпустит сертификат, и сайт по HTTPS не откроется.

## 1. Пользователь базы

Пароль пользователя базы создайте на сервере. В нём не должно быть символов `@ : / ? #`, иначе адрес базы разберётся неправильно. Вывод команды сохраните: он понадобится один раз.

```bash
openssl rand -hex 24
```

Пароль администратора Mongo лежит в `/opt/mongo/.env`, переменная `MONGO_INITDB_ROOT_PASSWORD`. В команду ниже подставьте его и пароль проекта. Пользователь видит только базу `support_summary`.

```bash
docker exec mongo mongosh --username root --password "ПАРОЛЬ-АДМИНИСТРАТОРА" --authenticationDatabase admin --eval 'db.getSiblingDB("support_summary").createUser({user:"support_summary",pwd:"ПАРОЛЬ-ПРОЕКТА",roles:[{role:"readWrite",db:"support_summary"}]})'
```

В ответе должно быть `"ok": 1`. Если пользователь уже создан, команду второй раз не выполняйте.

Проверьте, что порт `3001` свободен. Пустой вывод значит, что порт свободен. Если в выводе есть строка, возьмите `3002` и дальше везде пишите его вместо `3001`.

```bash
ss -ltn | grep ':3001'
```

## 3. Настройки приложения

Секреты свои, не из Отклика. Сначала создайте два значения и сохраните вывод.

Пароль на весь сайт. Его передают тестировщикам отдельно от ссылки. Имя пользователя при входе — любое.

```bash
openssl rand -base64 18
```

Секрет шифрования ключа ИИ. Создайте его один раз и потом не меняйте: иначе сохранённый ключ перестанет читаться.

```bash
openssl rand -base64 48
```

Теперь откройте файл настроек. Вторую команду выполняйте сразу после первой, в том же сеансе: так файл создаётся без доступа для остальных пользователей сервера.

```bash
umask 077
```

```bash
nano /opt/support-summary/.env
```

Вставьте этот текст. `ПАРОЛЬ-ПРОЕКТА` — пароль базы из шага 1. `ПАРОЛЬ-САЙТА` и `СЕКРЕТ-ШИФРОВАНИЯ` — два вывода команд выше. Провайдера, ключа и модели ИИ здесь нет: их вводят на сайте после запуска.

```dotenv
PORT=3000
MONGODB_URI=mongodb://support_summary:ПАРОЛЬ-ПРОЕКТА@mongo:27017/support_summary?authSource=support_summary
AI_REQUESTS_PER_HOUR=20
AI_REQUESTS_PER_DAY=300
DEMO_PASSWORD=ПАРОЛЬ-САЙТА
SETTINGS_SECRET=СЕКРЕТ-ШИФРОВАНИЯ
TRUST_PROXY=true
```

`AI_REQUESTS_PER_HOUR` — сколько сводок с ИИ можно запросить с одного адреса за час. `AI_REQUESTS_PER_DAY` — сколько таких сводок можно запросить на весь сервер за сутки. Числа выше можно оставить.

Закройте редактор и проверьте права файла:

```bash
chmod 600 /opt/support-summary/.env
```

Файл `.env` не копируйте в репозиторий и в чаты.

## 4. Запуск контейнера

Файл ниже лежит только на сервере. В репозиторий его не добавляйте.

```bash
nano /opt/support-summary/docker-compose.prod.yml
```

```yaml
services:
  app:
    build: .
    image: support-summary:local
    restart: unless-stopped
    ports:
      - "127.0.0.1:3001:3000"
    env_file: .env
    environment:
      TRUST_PROXY: "true"
    networks:
      - shared

networks:
  shared:
    external: true
    name: shared
```

Контейнер слушает порт 3000 внутри себя. С сервера он доступен только как `127.0.0.1:3001`. Сеть `shared` уже есть: через неё приложение видит контейнер `mongo` и не видит чужие проекты, которым эта сеть не указана.

Сборка идёт на сервере и в первый раз занимает несколько минут. Две отдельные команды:

```bash
cd /opt/support-summary
```

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Проверка. У сервиса `app` должно быть состояние `healthy`.

```bash
docker compose -f docker-compose.prod.yml ps
```

С сервера, без пароля сайта:

```bash
curl -fsS http://127.0.0.1:3001/api/health
```

Ответ: `{"status":"ok"}`. Если его нет, смотрите журнал. Причина пишется по-русски, например «Укажите адрес базы данных».

```bash
docker compose -f docker-compose.prod.yml logs --tail 100 app
```

## 5. Сайт в Caddy

Сначала сохраните текущий файл. В нём уже есть Отклик, этот блок не изменяйте.

```bash
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak
```

```bash
sudo nano /etc/caddy/Caddyfile
```

Добавьте блок в конец файла:

```caddy
ДОМЕН {
	encode gzip
	reverse_proxy 127.0.0.1:3001
}
```

Две отдельные команды. Вторую выполняйте только если первая закончилась без ошибки.

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
```

```bash
sudo systemctl reload caddy
```

Проверка с Мака. Печатается `{"status":"ok"}`. Этот адрес пароль не спрашивает.

```bash
curl -fsS https://ДОМЕН/api/health
```

Главную страницу откройте в браузере: `https://ДОМЕН/`. Браузер спросит пароль. Имя можно ввести любое, пароль — `ПАРОЛЬ-САЙТА`.

## 6. Подключение ИИ

1. Откройте сайт, введите пароль и перейдите в раздел «Подключение ИИ».
2. Выберите службу, вставьте ключ и впишите модель. Нажмите «Сохранить».
3. Ключ хранится в базе в зашифрованном виде и на сайте больше не показывается.

Если страница пишет, что сохранить ключ нельзя, в `.env` пустой `SETTINGS_SECRET`. Заполните его и выполните:

```bash
docker compose -f /opt/support-summary/docker-compose.prod.yml up -d
```

## 7. Ссылка для тестировщиков

Впишите `https://ДОМЕН/` в `ИНСТРУКЦИЯ.md`, в раздел «Самый простой способ — по ссылке». Пароль в этот файл не пишите: передайте его отдельно. Затем проверьте сайт по пункту 8.4 плана.

## Обновление

Данные в общей базе при обновлении сохраняются. Три отдельные команды:

```bash
cd /opt/support-summary
```

```bash
git pull
```

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Старые образы занимают место. Удалить можно только те, которые не используются ни одним контейнером. Базу эта команда не трогает.

```bash
docker image prune -f
```

## Резервная копия

Копия пишется в домашний каталог пользователя `deploy`. В архиве только база `support_summary`.

```bash
docker exec mongo mongodump --username root --password "ПАРОЛЬ-АДМИНИСТРАТОРА" --authenticationDatabase admin --archive --gzip --db support_summary > "$HOME/support-summary-$(date +%F).gz"
```

Восстановление заменяет текущие наборы, сводки, отзывы и сохранённый ключ ИИ данными из архива. Чужие базы не затрагиваются. Подставьте имя файла.

```bash
docker exec -i mongo mongorestore --username root --password "ПАРОЛЬ-АДМИНИСТРАТОРА" --authenticationDatabase admin --archive --gzip --drop --nsInclude "support_summary.*" < "$HOME/support-summary-ГГГГ-ММ-ДД.gz"
```

Ключ ИИ в копии зашифрован. Он прочитается, только если `SETTINGS_SECRET` тот же, что при сохранении.

## Остановка

```bash
docker compose -f /opt/support-summary/docker-compose.prod.yml stop
```

Контейнер останавливается, база остаётся. Не выполняйте `docker compose down -v` в `/opt/mongo`: эта команда стирает базы всех проектов.

Запуск после остановки:

```bash
docker compose -f /opt/support-summary/docker-compose.prod.yml start
```

## Безопасность

- На сайте обязателен `DEMO_PASSWORD`. Без него страница «Подключение ИИ» открыта всем: ключ посмотреть нельзя, но его можно заменить или удалить.
- Все, кто знают пароль, могут собирать сводки, менять свои копии наборов и настройки ИИ. Давайте пароль только тем, кто проверяет задание.
- Сайт открывается по HTTPS. Сертификат выпускает уже установленный Caddy, когда A-запись смотрит на этот сервер.
- Сводок с ИИ не больше `AI_REQUESTS_PER_HOUR` с одного адреса за час и не больше `AI_REQUESTS_PER_DAY` на весь сервер за сутки. Счётчики хранятся в памяти контейнера и обнуляются при перезапуске.
- На сайте не нужно вводить настоящие персональные данные.
- Если служба ИИ позволяет, поставьте на ключ месячный предел расходов.

## Если что-то не работает

| Что видите | Что сделать |
| --- | --- |
| Сборка оборвалась без понятной ошибки | На сервере не хватило памяти во время сборки. Посмотрите `docker compose -f docker-compose.prod.yml logs --tail 100 app`. |
| `{"status":"ok"}` нет на `127.0.0.1:3001` | Журнал контейнера. Частая причина — неверный пароль или имя базы в `MONGODB_URI`. |
| `https://ДОМЕН/api/health` не открывается, а локальная проверка жива | A-запись домена и `sudo journalctl -u caddy -n 100 --no-pager`. |
| Caddy не перезагрузился | Верните файл: `sudo cp /etc/caddy/Caddyfile.bak /etc/caddy/Caddyfile`, затем снова `sudo caddy validate --config /etc/caddy/Caddyfile` и `sudo systemctl reload caddy`. |
| Сайт открылся, браузер не спрашивает пароль | В `.env` пустой `DEMO_PASSWORD`. Для публичной ссылки так оставлять нельзя. |
| «Лимит запросов к ИИ исчерпан» | Подождите или увеличьте лимиты в `.env` и выполните `docker compose -f docker-compose.prod.yml up -d`. |
| Отклик перестал открываться после правки Caddy | Вы изменили чужой блок. Верните `/etc/caddy/Caddyfile.bak`, как в строке выше. |

## Чего не делать

Не публикуйте порт `27017` и не добавляйте `3001` в брандмауэр. Не запускайте вторую Mongo и не поднимайте Caddy из `deploy/docker-compose.vps.yml`. Не используйте базу `watch-reviews` и пользователя `otklik`. Не копируйте `.env` Отклика. Не выполняйте `docker compose down -v` в `/opt/mongo`.
