# Публикация на своём сервере (VPS)

Инструкция для того, кто устанавливает приложение на сервер. Тестировщикам она не нужна: им достаточно ссылки.

## Что получится

```
Интернет → Caddy (порты 80 и 443, сертификат HTTPS) → приложение (порт 3000) → MongoDB
```

Всё работает в Docker на одном сервере. Наружу открыт только Caddy. Порты приложения и базы не публикуются: Docker открывает опубликованные порты в обход брандмауэра `ufw`, поэтому закрыть их можно только так.

Файлы для сервера:

- `docker-compose.yml` — общий файл, тот же, что и для запуска на своём компьютере;
- `deploy/docker-compose.vps.yml` — дополнение для сервера: добавляет Caddy, закрывает порты приложения и базы, включает `TRUST_PROXY=true`;
- `deploy/Caddyfile` — настройки Caddy.

## Что нужно заранее

- Сервер с Linux, который поддерживает Docker Engine. Проверено на этом компьютере только с Docker Desktop. Сам сервер не проверялся.
- Не меньше 2 ГБ оперативной памяти: образ собирается прямо на сервере. Если памяти меньше, сборка может прерваться. Тогда добавьте файл подкачки или выберите сервер больше.
- Доступ к серверу по SSH с правами `sudo`.
- По желанию — домен. Запись типа A (и AAAA, если есть IPv6) должна указывать на IP-адрес сервера. С доменом сайт работает по HTTPS. Без домена — только по HTTP через IP-адрес.

## 1. Подготовка сервера

1. Установите Docker Engine и плагин Docker Compose по официальной инструкции для вашей системы: https://docs.docker.com/engine/install/. Команды зависят от системы и её версии, поэтому берите их оттуда.
2. Проверьте версию Compose:

   ```bash
   docker compose version
   ```

   Нужна версия 2.24 или новее: дополнение для сервера использует пометку `!reset`.
3. Если на сервере включён `ufw`, откройте SSH, 80 и 443:

   ```bash
   sudo ufw allow OpenSSH
   sudo ufw allow 80/tcp
   sudo ufw allow 443/tcp
   sudo ufw allow 443/udp
   ```

## 2. Код приложения

```bash
sudo mkdir -p /opt/support-summary
sudo chown "$USER" /opt/support-summary
git clone https://github.com/KirilGS/test-task.git /opt/support-summary
cd /opt/support-summary
```

Если репозиторий закрытый, понадобится доступ к нему с сервера: ключ развёртывания или токен GitHub только на чтение.

## 3. Настройки

```bash
cp .env.example .env
chmod 600 .env
```

Откройте `.env` в редакторе (например, `nano .env`) и измените строки:

| Переменная | Что вписать |
| --- | --- |
| `SETTINGS_SECRET` | Длинная случайная строка. Ею шифруется ключ ИИ в базе. Создайте её командой `openssl rand -base64 48` и вставьте результат. Не меняйте её потом: иначе сохранённый ключ ИИ перестанет читаться, и его придётся ввести заново. |
| `SITE_ADDRESS` | Уберите `#` в начале строки. Впишите домен, например `summary.example.ru`. Если домена нет, оставьте `:80`. |
| `COMPOSE_FILE` | Уберите `#` в начале строки. Значение не меняйте: `docker-compose.yml:deploy/docker-compose.vps.yml`. Тогда команды `docker compose` сами подключат дополнение для сервера. |
| `AI_REQUESTS_PER_HOUR` | Сколько сводок с ИИ можно сделать с одного IP-адреса за час. По умолчанию 20. |
| `AI_REQUESTS_PER_DAY` | Сколько сводок с ИИ можно сделать на весь сервер за сутки. По умолчанию 300. |
| `DEMO_PASSWORD` | Пароль на весь сайт. Обязателен для публичной ссылки, подробнее в разделе «Безопасность». Создайте его командой `openssl rand -base64 18` и передавайте тестировщикам отдельно от ссылки. Имя пользователя при входе — любое. |

Остальные строки не трогайте:

- `MONGODB_URI` для сервера задаёт `docker-compose.yml`, значение из `.env` не используется.
- `TRUST_PROXY` для сервера включает `deploy/docker-compose.vps.yml`.
- `APP_PORT` на сервере не используется: приложение доступно только через Caddy.
- Провайдера, ключа и модели ИИ в этом файле нет и добавлять их не нужно. Их вводят на странице «Подключение ИИ» после запуска (шаг 5).

Файл `.env` содержит секрет. Не копируйте его в репозиторий и в чаты.

## 4. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает несколько минут. Проверьте состояние:

```bash
docker compose ps
```

У `app` и `mongo` должно быть `healthy`, у `caddy` — `Up`.

Проверьте ответ сервера. С доменом:

```bash
curl -fsS https://summary.example.ru/api/health
```

Без домена:

```bash
curl -fsS http://<IP-адрес сервера>/api/health
```

Ответ должен быть `{"status":"ok"}`. Эта проверка работает без пароля, а остальные страницы сайта браузер откроет только после ввода `DEMO_PASSWORD`.

С доменом Caddy получает сертификат при первом запуске. Если HTTPS не заработал, посмотрите журнал:

```bash
docker compose logs --tail 100 caddy
```

Частые причины: запись A указывает не на этот сервер, порты 80 или 443 закрыты у провайдера сервера.

## 5. Подключение ИИ

1. Откройте сайт в браузере, введите пароль и перейдите в раздел «Подключение ИИ».
2. Выберите службу, вставьте ключ и впишите модель. Нажмите «Сохранить».
3. Ключ хранится в базе в зашифрованном виде и на сайте больше не показывается.

Если страница пишет, что сохранить ключ нельзя, значит, в `.env` не задан `SETTINGS_SECRET`. Задайте его и выполните `docker compose up -d`.

## 6. Ссылка для тестировщиков

Впишите адрес сайта в `ИНСТРУКЦИЯ.md`, в раздел «Самый простой способ — по ссылке». Сам пароль в файл не пишите: передайте его тестировщикам отдельно. Затем проверьте сайт по пункту 8.4 плана.

## Обновление

```bash
cd /opt/support-summary
git pull
docker compose up -d --build
```

Данные в базе при этом сохраняются. Старые образы занимают место на диске. Удалить неиспользуемые образы можно командой `docker image prune -f`. Она не трогает базу.

## Резервная копия базы

Сделать копию:

```bash
docker compose exec -T mongo mongodump --archive --gzip --db support_summary > "backup-$(date +%F).gz"
```

Восстановить из копии. Внимание: `--drop` заменяет текущие данные данными из копии.

```bash
docker compose exec -T mongo mongorestore --archive --gzip --drop < backup-ГГГГ-ММ-ДД.gz
```

Ключ ИИ в копии зашифрован. Он прочитается, только если `SETTINGS_SECRET` тот же, что при сохранении.

## Остановка

```bash
docker compose stop
```

Не выполняйте `docker compose down -v`: эта команда удаляет базу со всеми наборами, сводками и отзывами.

## Безопасность

- **На сайте стоит пароль `DEMO_PASSWORD`.** Без него страница «Подключение ИИ» открыта всем: посетитель не может увидеть ключ, но может заменить его своим или удалить. Отдельной защиты этой страницы в приложении нет, поэтому публиковать сайт без пароля нельзя.
- **Все, кто знает пароль, имеют одинаковые права:** они могут формировать сводки, менять свои копии наборов и настройки ИИ. Давайте пароль только тем, кто проверяет задание.
- **Пароль передаётся вместе с каждым запросом.** С доменом он защищён HTTPS. Без домена сайт работает по HTTP, и пароль идёт по сети открытым текстом. Для публичной ссылки лучше использовать домен.
- **Расход ИИ ограничен:** не больше `AI_REQUESTS_PER_HOUR` сводок с ИИ с одного IP-адреса в час и `AI_REQUESTS_PER_DAY` на весь сервер в сутки. Счётчики хранятся в памяти приложения и обнуляются при перезапуске.
- На сайте не нужно вводить настоящие персональные данные. Об этом предупреждает жёлтая плашка вверху страницы.
- Поставьте у провайдера ИИ месячный лимит расходов на ключ, если провайдер это позволяет.

## Если что-то не работает

| Что видите | Что проверить |
| --- | --- |
| Сборка прервалась без понятной ошибки | Не хватило памяти. Добавьте файл подкачки или возьмите сервер с большим объёмом памяти. |
| `docker compose` пишет про неизвестную пометку `!reset` | Старая версия Compose. Обновите Docker по официальной инструкции. |
| `app` не становится `healthy` | `docker compose logs --tail 100 app`. Сервер пишет причину по-русски, например «Укажите адрес базы данных». |
| Сайт открывается по IP-адресу, но не по домену | Запись A домена и журнал Caddy: `docker compose logs --tail 100 caddy`. |
| Сводка с ИИ отвечает «Лимит запросов к ИИ исчерпан» | Сработали ограничения. Подождите или увеличьте `AI_REQUESTS_PER_HOUR` и `AI_REQUESTS_PER_DAY`, затем выполните `docker compose up -d`. |
